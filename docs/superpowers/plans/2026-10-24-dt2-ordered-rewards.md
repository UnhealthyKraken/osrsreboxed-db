# DT2 ordered reward pipeline implementation plan

**Goal:** Execute the four source-stated normal DT2 loot chains and persistent vestige/first-receipt state without treating effective marginal rates as independent rolls.
**Architecture:** Canonical Wiki-paragraph parsing produces an ordered exclusive reward chain and an independent exclusive clue group. Generic NpcDrops executes that contract; a shared ForgottenFourRewards plugin owns player persistence. Boss encounter modules and Claude-owned clues/client features are untouched.
**Tech stack:** Existing Python Wiki parser/schema/exporter, CommonJS plugin events, real item/NPC/Player APIs and Node/pytest regressions.
**Approved spec:** Coordinating agent approved `reward_chain` ordered stages, conditional unique weights, first-received eligibility, cyclic vestige progression and synchronous reward-state/commit events. All four DT2 source pages qualify structurally; no table/NPC-ID override.
